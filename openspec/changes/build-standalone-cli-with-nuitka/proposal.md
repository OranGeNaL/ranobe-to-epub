## Why

Единственный способ запустить утилиту сейчас — поставить Python 3.14 и uv (`uv run`), либо установить пакет через `pip`/`pipx`. Это отсекает всех, у кого нет Python нужной версии, и делает установку отдельным шагом со своими проблемами. Публикуемые на GitHub Releases самодостаточные бинарные файлы позволяют скачать один файл и сразу запустить его.

## What Changes

- Появляется автоматизированная сборка самодостаточного исполняемого файла компилятором **Nuitka**, запускаемая в GitHub Actions.
- Появляется матричная сборка под три цели: **Linux x86_64**, **Windows x86_64**, **macOS arm64**. Каждая цель собирается на своём подходящем раннере; кросс-компиляция не используется.
- По тегу `v*` пайплайн создаёт GitHub Release и прикрепляет к нему готовые бинарные файлы с именами, однозначно указывающими платформу и архитектуру: `ranobelib-epub-linux-x86_64`, `ranobelib-epub-macos-arm64`, `ranobelib-epub-windows-amd64.exe`.
- Появляется отдельный workflow для проверок на каждом pull request и на `main`: линтер и тесты. Релизный пайплайн опирается на эти проверки, а не дублирует их.
- Релизный пайплайн можно запустить вручную для проверки сборки без публикации релиза.

## Capabilities

### New Capabilities
- `standalone-build`: сборка самодостаточного бинарного файла утилиты компилятором Nuitka, запуск проверок и сборки в GitHub Actions, публикация готовых файлов в GitHub Releases.

### Modified Capabilities
- (пусто) — поведение самой утилиты (CLI, TUI, сборка EPUB, фильтрация символов) не меняется. Изменяется только способ поставки.

## Impact

- **CI/CD**: добавляются `.github/workflows/ci.yml` и `.github/workflows/release.yml`. Для создания релиза достаточно прав `contents: write` у стандартного `GITHUB_TOKEN`, дополнительные секреты не нужны.
- **Зависимости разработки**: `nuitka` и его зависимости добавляются в группу `dev` в `pyproject.toml`, чтобы локальная сборка и CI использовали один и тот же инструмент.
- **Релизы**: в GitHub Releases появляются бинарные файлы; это дополняет существующую установку через uv, а не заменяет её.
- **Минимальная поддерживаемая система**: бинарные файлы требуют только базовые системные библиотеки целевой ОС; Python, uv и любые пакеты на машине пользователя не нужны.
- **macOS Intel**: не покрывается этим изменением. Единственный способ собрать `x86_64` для macOS — платные larger-раннеры GitHub, а компиляция universal2 не поддерживается начиная с Nuitka 4.x.
