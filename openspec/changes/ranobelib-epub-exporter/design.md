## Context

Проект greenfield: в репозитории нет кода, только `openspec/`. Поэтому design опирается на результаты живой разведки сайта, а не на существующую архитектуру.

Установленные факты (проверены запросами к сайту на момент планирования):

- **`ranobelib.ru` мёртв** — домен отдаёт `301` на `archa.ge` (калькулятор ArcheAge); `ranobelib.org` — парковочная страница «домен продаётся». Актуальная площадка — **`ranobelib.me`**, это инстанс **Mangalib**.
- **Страница книги — SPA.** По ссылке `/ru/book/94231--rezero-...?section=chapters` отдаётся 8.5 КБ пустой оболочки с `<div id="app">` и `window.__SEO_STRUCTURE__ = []`. Контента в HTML нет; скоринг HTML невозможен в принципе.
- **API найден в бандле фронтенда**, а не по документации: `https://api.cdnlibs.org/api`. Ровно этот хост, а не `/api` на самом сайте.
- **WAF**. Минимально необходимая комбинация, проверенная перебором: `Site-Id: 3` + `Origin: https://ranobelib.me` + `Referer: https://ranobelib.me/`. Без `Origin`/`Referer` — `403` с HTML-телом (615 байт) от nginx, даже с браузерным `User-Agent`. `User-Agent` значения не имеет.
- **Эндпоинты** (все отвечают `200`, проверены на книге `94231--...`):
  - `GET /manga/{slug_url}` → метаданные книги (3 КБ)
  - `GET /manga/{slug_url}/chapters` → **весь список глав одним ответом, 741 КБ на 735 глав, пагинации нет**
  - `GET /manga/{slug_url}/chapter?volume={V}&number={N}&branch_id={B}` → текст; без `volume` приходит `422`
- **`slug_url` лежит прямо в пользовательской ссылке** (`94231--rezero-...`), отдельный поиск не нужен.
- **Текст главы — ProseMirror-JSON**, а не HTML: `{type: "doc", content: [...]}`. Обойдено 9 глав; встреченные узлы: `doc`, `paragraph` (1562), `text` (1693), `heading` (12), `image` (11), `hardBreak` (227), `horizontalRule` (24), `blockquote` (3); марки `italic` (37), `bold` (7). Набор TipTap-стандартный, поэтому реализуем шире, чем наблюдали.
- **Изображения приходят отдельным массивом** `attachments[]` с полями `name`, `width`, `height` и **относительным** `url` вида `/uploads/ranobe/94231/chapters/3422985/<uuid>.png`. Узлы `image` в ProseMirror ссылаются на вложение по имени (`attrs.images[].image` = `<uuid>`), а не по пути — нужен join по имени. Абсолютный URL получается префиксованием **origin сайта**: `https://ranobelib.me/uploads/...` отдаёт `image/png`. Хосты `img2.imglib.info` и `img3.cdnlibs.org` для этих путей отдают `404`/пустое тело — использовать нельзя.
- **Ветки перевода**: у первых глав книги по 3 ветки (DifferLex, re:Translators, Loxotron's), у остальных — по 1. Первая ветка совпадает с `id` главы и является актуальной.
- **Ключ к Site-Id**: `<html data-id="3">` на ranobelib.me соответствует `Site-Id: 3`. На том же хосте есть и другие площадки (Mangalib, Anilib, Slashlib) с другими id, поэтому значение вынесено в конфигурацию клиента.
- **Возрастное ограничение — самодекларация, а не защита.** В бандле фронтенда: метка `18+` = `ageRestriction.id = 4`; `18+ (RX)` = `id = 5` и доступна только для сайтов Hentai/Yaoi/Manga, то есть **на RanobeLib (site 3) RX не существует**. Модалка «Мне есть 18+» — клиентский диалог, отметка хранится в Pinia-сторе `tipMessages` (localStorage) и на сервер не отправляется. Флаг `registrationOnly = notAuthorized && (id === 5 || site ∈ {Hentai, Yaoi, Manga})` на ranobelib.me всегда `false`. Эмпирическое подтверждение: текст книги с меткой `18+` получен без авторизации и без подтверждения.
- **Структура глав даёт готовую иерархию.** Поля `volume` (всегда целое, 1..46) и `number` (639 целых + 96 дробных). Дробные значения — **побочные истории и интерлюдии**: `1.22.5`, `1.22.6` — «Побочная История» к главе 22. Пары `(volume, number)` уникальны для всех 735 глав.
- **`number_secondary` — не уровень иерархии.** Он повторяет номер тома (в томе 2 `sec=2`, в томе 46 `sec=46`), и ни в одном из 706 названий с `sec != 1` нет «часть N». Включение дало бы бессмысленное `46.37.46`.
- **CrossPoint** — прошивка e-ink ридеров на ESP32 (Xteink и совместимые, ~8.1k звёзд). Рендеринг идёт через `expat` и собственные субсетированные шрифты `EpdFont`. Набор встроенных шрифтов задан пресетом `builtin` в `lib/EpdFont/scripts/fontconvert_sdcard.py`. Именованные HTML-сущности распознаются только по таблице из ~250 записей (`htmlEntities.cpp`, унаследована из `atomic14/diy-esp32-epub-reader`); числовые ссылки `&#8212;` поддерживаются.
- **Замеры**: 20 последовательных запросов за 6 с — все `200`, ни одного `429`. Сжатие: картинка 5014 КБ / 2210×1582 RGBA → JPEG 1280px q80 = **229 КБ (22×)**, WebP q82 = 352 КБ, то есть WebP проиграл.
- **Зависимости**: `textual` 8.2.8, `httpx` 0.28.1, `pillow` 12.3.0 — все ставятся на Python 3.14.6 (wheel'ы есть).

## Goals / Non-Goals

**Goals:**
- Слой сайта полностью изолирован: `epub-build` и `tui-cli` не знают ни про HTTP, ни про формат ответа Mangalib. Их вход — dataclass-модели, выход — файл или отчёт.
- Сборка EPUB собственным кодом, чтобы полностью контролировать XHTML, встраивание картинок и метаданные — без борьбы с ограничениями сторонней библиотеки.
- Ни один сбой (недоступная глава, битая картинка, неизвестный узел) не должен уничтожать уже собранный результат.
- Один и тот же код сборки для TUI и CLI: решение «как выбрать перевод» и «куда писать прогресс» — единственное различие.

**Non-Goals:**
- Не обходим авторизацию и платный доступ. Главы, которые сервер не отдаёт без учётной записи, попадают в отчёт как недоступные — см. спецификацию `book-source-ranobelib`. Подтверждение возраста `18+` — не обход, а фиксация декларации пользователя (решение 11).
- Не поддерживаем другие площадки Mangalib-семейства (`anilib.me`, `mangalib.me`, `slashlib.me`, `hentailib.me`). Но клиент параметризуется `site_id` и базой API, потому что это бесплатно, а `Site-Id` — обязательный заголовок.
- Не делаем галерею сайта, поиск по каталогу, авторизацию, обновление ранее скачанной книги (инкрементальная докачка).
- Не даём пользователю редактировать текст глав внутри утилиты.

## Decisions

### 1. Источник данных — REST API, не HTML

Разбор HTML отпал сам собой: страница — пустая SPA-оболочка. Альтернативы вроде headless-браузера (Playwright) отброшены по трём причинам: тяжёлая зависимость ради задачи, у которой есть готовый JSON-интерфейс; хрупкость — селекторы привязаны к вёрстке; на порядок медленнее. Итог: парсим только JSON.

**Следствие**: при поломке вёрстки сайта утилита продолжит работать. При поломке контракта API — нет. Это осознанный размен: контракт версионируется вместе с фронтендом, вёрстка — нет.

### 2. `slug_url` извлекается из ссылки, а не ищется

Пользовательская ссылка уже содержит `{id}--{slug}`, который и есть `slug_url` для всех трёх эндпоинтов. Отдельный запрос «найти книгу по имени» не нужен. Разбор — чистая функция над URL без сети, поэтому тестируется без фикстур.

Отвергли: поиск по названию (лишний запрос, неоднозначность результатов) и использование голого числового `id` (проверено — `GET /manga/94231` возвращает `404`, числовой `id` не принимается).

### 3. Три слоя, зависимости строго внутрь

```
tui-cli  →  book-source-ranobelib  →  HTTP
   ↓
epub-build  →  ProseMirror-JSON + attachments (модели, без сети)
```

`epub-build` — чистая функция `(Book, list[Chapter], options) -> (bytes, Report)`. Благодаря этому она тестируется на зафиксированных JSON без сети и мгновенно. Единственное исключение — загрузка картинок; чтобы не размывать границу, загрузчик передаётся в неё как **внедряемая функция** (`fetch(url) -> bytes`), а не создаётся внутри. В проде это обёртка над `httpx`, в тестах — заглушка.

### 4. ProseMirror → XHTML пишем сами

ProseMirror-JSON — простой и стабильный формат: плоское дерево с `type`, `attrs`, `marks`, `content`. Конвертер — рекурсивный обход на ~120 строк с таблицей `node_type -> XHTML-тег`.

Отвергли `pandoc`/`ebook-convert` как внешние бинарные зависимости: они тянут за собой цепочки, требуют brew/apt, и их версии дрейфуют, из-за чего падает воспроизводимость сборки. Отвергли рендер ProseMirror через JS-движок — ради 8 типов узлов это несоразмерно.

**Ключевое свойство конвертера**: `default`-ветка для неизвестных узлов пишет предупреждение в отчёт и пропускает узел. Наблюдали 8 типов, поддерживаем 12 — запас на `listItem`, `link`, `codeBlock`, но полнота схемы TipTap не гарантирована никогда, поэтому деградация обязана быть безвредной.

### 5. EPUB 3 собираем через `zipfile`

EPUB — это zip с жёсткими требованиями к структуре, а не сложный формат. Сборка: `zipfile.ZipFile` + рукописные `container.xml`, `package.opf`, `nav.xhtml`, `toc.ncx`. Обязательные тонкости, которые закрываем явно:
- `mimetype` — **первая** запись архива, без сжатия (`ZIP_STORED`), иначе часть читалок отвергает файл;
- `nav.xhtml` — EPUB 3, `toc.ncx` — для старых читалок (пишем оба);
- обложка объявляется в OPF дважды: как `meta` (`cover`) и как `item` с `properties="cover-image"`;
- `dc:identifier` — детерминированный (хеш `site_id` + `slug_url`), чтобы повторная сборка давала тот же файл.

Отвергли `ebooklib`: ради ~40 строк XML он тянет транзитивные зависимости и встаёт на версию библиотеки, которую придётся обновлять вслепую. Ручная сборка даёт прямой контроль над `dc:*`, порядком глав и встраиванием сжатых JPEG — то есть ровно над тем, что здесь и нужно настроить.

### 6. Картинки: JPEG 1280px q80, по умолчанию с лимитом

Обосновано замером на реальном файле (22× экономии при визуально приемлемом качестве). Важная деталь: исходники приходят в **RGBA**, а JPEG альфы не умеет — прозрачные области заливаем белым через `Image.alpha_composite` на белом фоне, иначе получим чёрные прямоугольники.

WebP проверен и отклонён: при том же качестве больше по размеру (352 против 229 КБ) и хуже поддерживается EPUB 3. Флаг `--max-image-mb 0` отключает сжатие целиком — на случай, когда качество важнее размера.

### 7. Ветки перевода: дефолт + покрытие, а не «молчаливый выбор»

Уникальность задачи: один перевод может покрывать 90 глав из 735. Молчаливый выбор дал бы книгу, на 645 главах которой текст от другого переводчика — пользователь узнаёт об этом только при чтении.

Поэтому выбор — двухчастный:
1. **Дефолт** — `branches[0]` (актуальная ветка) для каждой главы, где она есть.
2. **Покрытие** — до начала загрузки вычисляется, сколько глав покрывает выбранный перевод. Если покрытие неполное, TUI показывает предупреждение «90 из 735» **до** начала загрузки и даёт вернуться к выбору. Это дешёвый расчёт по уже загруженному списку глав, отдельных запросов не требует.

В TUI перевод выбирается по имени команды (`--team` в неинтерактивном режиме). Для глав без выбранной команды применяется дефолтная ветка — но такие главы попадают в список явно непокрытых, чтобы неполнота была видна, а не молчаливой.

### 8. TUI — `textual`, а не prompt_toolkit/curses

`textual` даёт готовые виджеты (прогресс-бар, таблицы, формы), корректный ресайз и офлайн-тестирование через `run_test()` — это важно: TUI можно покрыть тестами без реального терминала. `prompt_toolkit` пришлось бы дополнять всем этим вручную, `curses` — писать свой рендеринг.

**Ключевое решение по concurrency**: сеть выполняется в пуле потоков (`asyncio` + `httpx.AsyncClient` для I/O и `asyncio.to_thread` для Pillow), результаты отдаются в UI через `asyncio.Queue`. Альтернатива — `textual.worker`; отвергли, потому что при 735 главах управление через очередь оказалось бы тем же решением, но с лишним слоем.

### 9. Неинтерактивный режим — отдельный путь ввода, тот же код

Различия сведены к двум точкам: **источник решений** (`Prompter` из TUI vs значения флагов) и **приёмник прогресса** (виджет TUI vs stdout). Сборка, HTTP и EPUB-код — общие. Так гарантируется, что два режима не разъедутся по поведению.

### 10. Проверка ошибок и отчёт — единый объект `Report`

Все части собирают `Report`: недоступные главы с причинами, нескачанные картинки, неизвестные узлы, итоговый размер. TUI рендерит его таблицей, CLI печатает текстом. Частичный EPUB допускается всегда; код возврата ненулевой только если **не собрано ни одной главы**.

### 11. Подтверждение 18+ автоматически, обход авторизации — нет

Запрос «обходить 18+ всегда и автоматически» сначала разобран по существу, а не принят на веру. Проверено, что на ranobelib.me этот гейт **не является мерой защиты**:

| Что установлено | Источник |
|---|---|
| `18+` = `ageRestriction.id = 4`; `18+ (RX)` = `id = 5` | `/constants?fields[]=ageRestriction` |
| `id = 5` доступен только для сайтов 4, 2, 5 (Hentai/Yaoi/Manga) — **не для 3 (RanobeLib)** | тот же ответ, `site_ids` |
| Отметка «Мне есть 18+» живёт в Pinia-сторе `tipMessages`, персистится в localStorage и на сервер не уходит | бандл: `persist:{pick:["settings",…,"tipMessages",…]}` |
| `registrationOnly = notAuthorized && (id === 5 \|\| site ∈ {Hentai,Yaoi,Manga})` → на ranobelib.me всегда `false` | бандл, `showAdultCautionDialog` |
| Текст книги с меткой `18+` получен без авторизации и без подтверждения | фактический запрос к API |

Итого: сервер отдаёт контент открыто, а сайт просит читателя **самому подтвердить**, что ему есть 18. «Автоподтверждение» здесь — это фиксация возрастной декларации самого пользователя (он прямо заявляет её в запросе на утилиту), а не нейтрализация защиты.

Поэтому граница проведена так:
- **`id <= 4` (в т.ч. `18+`) — подтверждаем автоматически**, получаем содержимое обычным `GET`, фиксируем факт в отчёте. Никаких дополнительных запросов, подмены заголовков или обходов не требуется, потому что блокировки нет.
- **`id = 5` (RX) и любые отказы по причине авторизации — не обходим.** Это настоящий контроль доступа; предпринимать повторные попытки с подменой учётных данных, проксированием или иными средствами сокрытия смысла не имеет. Такие главы — в отчёт.

**Почему это не ущемляет задачу**: RX на ranobelib.me не существует в принципе (его нет в `site_ids`), поэтому запрещённая ветка на целевом сайте недостижима. Плата за границу — нулевая.

Альтернатива «полностью молчаливый обход всего подряд» отклонена: она означала бы, что утилита пробует обходить и авторизацию тоже, а это уже выходит за рамки «скачать книгу, которую пользователь и так читает».

### 12. Номер главы = `{volume}.{number}`, `number_secondary` отброшен

Запрошен формат «родительский → дочерний» с примерами `1.25` и `15.12`. Данные сайта уже кодируют ровно эту иерархию, поэтому номер строится без изобретения собственной схемы:

```
{volume}.{number}        том 1, глава 25   → 1.25      ✓ пример из запроса
{volume}.{number}        том 15, глава 12  → 15.12     ✓ пример из запроса
{volume}.{chapter}.{part}  1.22.5, 1.22.6   → 1.22.5    побочная история к главе 22
```

Ключевой факт: 96 из 735 `number` — дробные, и это **побочные истории и интерлюдии** («Побочная История | …», «Интерлюдия | …»), то есть дочерние материалы глав. Использование `number` дословно даёт трёхуровневый номер автоматически и без специальных правил.

`number_secondary` отброшен после проверки на всех 735 главах: он **повторяет номер тома** (`sec == volume` почти всегда), а в 706 случаях с `sec != 1` ни в одном названии нет «часть N». Включение дало бы `46.37.46` — вводящий в заблуждение номер с несуществующим уровнем.

Пары `(volume, number)` уникальны для всех 735 глав, так что коллизий на реальных данных нет. Тем не менее спецификация требует разрешать коллизии порядковым суффиксом: это защита от тихой подмены двух глав, если у другой книги структура окажется иной.

Номер попадает в три места: заголовок главы, пункт `nav.xhtml` и имя файла — иначе на e-ink устройстве невозможно ориентироваться в книге на 735 глав.

### 13. Фильтрация символов по пресетам шрифтов CrossPoint

Вместо собственного списка «плохих» символов используем **набор диапазонов, реально вшитых в прошивку** — пресет `builtin` из `lib/EpdFont/scripts/fontconvert_sdcard.py`. Это источник истины: разработчики CrossPoint комментируют его как «Matches the built-in font intervals from fontconvert.py exactly».

Профиль по умолчанию `builtin` покрывает 15 диапазонов: ASCII, Latin-1, Latin Ext-A, кириллица `U+0400–U+04FF`, комбинирующие диакритики, General Punctuation (`U+2000–U+206F` — тире, кавычки, многоточие), валюта, стрелки, матоператоры, лигатуры `U+FB00–U+FB06`. Вне него остаётся всё, что типично для ранобэ-сайта: эмодзи и вся астральная плоскость (математические алфавитные `U+1D400+`, которые встречаются в никах переводчиков вроде `✦E𝔵𝒶м𝓈i✦`), Box Drawing, CJK, полноширинные формы.

Три важных следствия, повлиявших на реализацию:

1. **Удаление по графемам, а не по кодовым точкам.** Эмодзи — это кластеры с `U+200D` (ZWJ), селекторами вариации `U+FE0F` и модификателями тона кожи `U+1F3FB–U+1F3FF`. Поточечное удаление оставило бы осиротевшие невидимые символы и испортило бы последующую разбивку на слова в движке CrossPoint. Поэтому фильтр работает по кластерам (extended grapheme clusters) — средствами stdlib `unicodedata` не обойтись, нужен небольшой разбор либо проверка по кодам ZWJ/вариаций.
2. **Профиль настраиваемый.** Устройство может получить шрифт с SD-карты (`symbols`, `cjk`, `hangul` — те же пресеты), поэтому фильтр не «выжигает» символы безусловно: `builtin` по умолчанию, `builtin+symbols`, `+cjk`, `full` для книг, которые читаются на обычном ридере.
3. **Никаких именованных сущностей.** CrossPoint умеет декодировать только ~250 именованных сущностей из своей таблицы. Числовые ссылки он понимает. Поэтому XHTML генерируется как чистый UTF-8 — это и проще, и безопаснее; требование «не использовать сущности вне таблицы» выполняется по построению.

Удаление символов **никогда не молчит**: число удалённых символов и затронутых глав попадает в отчёт. Иначе фильтр незаметно испортил бы текст, а на e-ink экране заметить это невозможно.

## Risks / Trade-offs

- **Контракт API не документирован и может измениться без предупреждения** → обернуть все вызовы в клиент, изолированный в одном модуле; фикстуры реальных ответов хранить в тестах, чтобы падение было заметно сразу. В тексте README указать, что API Mangalib не гарантирует обратной совместимости.
- **WAF-эвристика может ужестоться** → вынести `Site-Id`, `Origin`, `Referer` в одну конфигурацию клиента; при `403` с HTML-телом давать отдельное сообщение именно про заголовки, а не про данные, иначе диагностика уводит в сторону.
- **Книга на 735 глав — это ~100 МБ JSON только в ProseMirror** (замер: одна глава 117–261 КБ). Нужен потоковый режим: главы обрабатываются и упаковываются по мере поступления, а не накапливаются в памяти. Ограничение — список глав целиком в памяти (741 КБ), это приемлемо и зафиксировано как решение.
- **Фильтрация символов необратима.** Удалённые эмодзи и символы из астральной плоскости вернуть нельзя, а на обычном ридере они выглядели бы нормально. Поэтому профиль `full` существует и по умолчанию **не** выбран; пересборка с другим `--charset` требует повторного скачивания глав, так как отфильтрованный текст нигде не кешируется. Если в тексте регулярно встречаются символы вне `builtin`, полезнее поставить шрифт с SD-карты, чем расширять профиль вслепую.
- **Пресет `builtin` привязан к текущей версии прошивки.** CrossPoint может расширить набор при обновлении. Смягчение: профиль задаётся константой с ссылкой на исходник (`lib/EpdFont/scripts/fontconvert_sdcard.py`) и на версию пресета, чтобы расхождение обнаруживалось осознанно. Автоматически тянуть список шрифтов с устройства нельзя — сборка идёт на десктопе.
- **Дробные номера глав выглядят непривычно** (`1.22.5`). Но они точно отражают структуру сайта, где это побочные истории, — и альтернатива (склеить в `1.22-5` или проигнорировать) исказила бы соответствие источнику.
- **Прогресс TUI при 735 главах обновляется слишком часто** → перерисовывать не чаще ~10 раз в секунду, иначе терминал захлебывается; прогресс-бар Textual это умеет, но throttle всё равно нужен для собственного счётчика.
- **Троттлинг увеличивает время сборки** → 735 глав при 4 req/s ≈ 3 минуты плюс загрузка картинок. Оправдано: агрессивный режим без лимита — это риск бана по IP, цена которого выше потери трёх минут.
- **Подтверждение `18+` автоматическое** → пользователь не увидит диалога и решит, что ограничение проигнорировано (решение 11: на ranobelib.me это самодекларация, а не защита). Чтобы решение не выглядело молчаливым, факт подтверждения и число подтверждённых глав явно попадают в отчёт. Настоящие ограничения (авторизация, `18+ (RX)` на других площадках) не обходятся — такие главы видны в отчёте как недоступные.
- **NCX deprecated в EPUB 3** → пишем и `nav.xhtml`, и NCX: первые игнорируют NCX, вторые без него не откроются.
- **Альфа-канал теряется при JPEG** → сознательный размен: прозрачные области заливаются белым. Для сканов иллюстраций это норма, для иллюстраций с прозрачным фоном — видимое отличие от сайта. Уходит параметром `--no-images`.
- **Тесты зависят от зафиксированных JSON-фикстур** → фикстуры берутся из реальных ответов и обрезаются; при изменении формата тесты покажут правдоподобный, но устаревший результат. Смягчается `contract`-тестом, который при наличии сети делает один реальный запрос и сверяет ключи.

## Migration Plan

Применимо не полностью: существующих пользователей и данных нет, откатывать нечего. Порядок внедрения — как в tasks.md, каждый шаг оставляет проект в рабочем состоянии:

1. Каркас `uv`-проекта, модели, парсинг ссылки — работает и тестируется без сети.
2. HTTP-клиент + фикстуры — появляется возможность собрать книгу «всё в одну главу».
3. ProseMirror → XHTML + сборка EPUB 3 — появляется читаемый файл.
4. Изображения и сжатие — появляется полноценная книга.
5. TUI и CLI-флаги — появляется интерфейс.

Откат на любом шаге — удаление пакета; внешних систем, схем и миграций данных не затрагивается. Формат EPUB — append-only артефакт в пользовательской папке; перезапись должна требовать явного `--overwrite` (в текущей версии — новое поведение, не ломающее, но зафиксированное).

## Open Questions

- **Есть ли на других книгах узлы вне наблюдённых восьми.** Мы реализовали 12 типов TipTap и безопасную деградацию для остальных; при фактическом появлении нового типа он попадёт в отчёт как предупреждение и потребует одной строки в таблице конвертера. Спецификации и разбиение задач это не меняют.
- **`attachments` против `pages` в ответе главы.** В коде фронтенда для манги используется `pages`, для ранобэ — `attachments`; в наблюдённых ответах `pages` был `null`. Поддержка обоих ключей тривиальна, но включается по факту появления, а не предположением.
- **Идентификатор издателя (`dc:publisher`) и переводчик в OPF.** Данные команд-переводчиков доступны (`branches[].teams[]`), но включать их в метаданные — решение по оформлению, а не по функциональности; на specs и задачи не влияет.
