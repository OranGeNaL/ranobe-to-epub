## ADDED Requirements

### Requirement: Построчный журнал сборки

В неинтерактивном режиме система SHALL печатать в stdout отдельную строку на каждую главу в порядке чтения — как для успешно собранных, так и для недоступных — с номером, названием и статусом, а для недоступных — с подробной причиной. Строки журнала SHALL следовать сразу по мере поступления событий, а не одним блоком в конце.

В TUI система SHALL предоставлять разворачиваемую (переключаемую) панель с теми же сообщениями по загружаемым главам. Панель SHALL обновляться по мере поступления событий, MUST NOT блокировать интерфейс и MUST NOT принудительно прокручиваться при новых записях. Для книги в сотни глав панель SHALL оставаться работоспособной.

#### Scenario: Строка на каждую главу в текстовом режиме
- **WHEN** сборка 20 глав выполняется с `--no-tui`
- **THEN** stdout содержит 20 строк журнала, по одной на главу, в порядке номеров

#### Scenario: Строка пропуска содержит причину
- **WHEN** глава недоступна в текстовом режиме
- **THEN** её строка содержит номер, название и подробную причину

#### Scenario: Панель журнала в TUI
- **WHEN** идёт сборка в TUI
- **THEN** интерфейс содержит панель журнала с сообщениями по загружаемым главам

#### Scenario: Журнал сворачивается и разворачивается
- **WHEN** пользователь переключает панель журнала
- **THEN** её видимость меняется, а сборка продолжается без прерывания

#### Scenario: Медленный сервер не блокирует журнал
- **WHEN** сервер отвечает медленно
- **THEN** интерфейс и панель журнала продолжают обновляться без зависания

#### Scenario: Большая книга не перегружает панель
- **WHEN** собирается книга из 735 глав
- **THEN** панель показывает журнал и остаётся отзывчивой
