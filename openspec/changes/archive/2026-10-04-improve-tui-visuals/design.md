## Context

Текущий TUI (`src/ranobelib_epub/tui/app.py`) — шесть экранов на `textual` 8.2.8: `LinkScreen`, `TranslationScreen`, `MetadataScreen`, `ConfirmScreen`, `ProgressScreen`, `ReportScreen`. Весь стиль — один блок CSS на `ExporterApp` с точечными правилами; обложки выбираются текстовым `Select` с метками вида «Том 1 (id=18021734)», изображения нигде не показываются. Тесты (`tests/test_tui.py`) гоняют `App.run_test()`, не поднимая сеть: загрузка метаданных и сборка внедряются через конструктор `ExporterApp`. Мотивация — см. `proposal.md — Why`.

`textual` 8.2.8 не имеет встроенного виджета картинок (официальный FAQ: в roadmap). Совместимый сторонний виджет `textual-image` 0.14.1: требует Python >=3.12 (проект на 3.14), `pillow>=10.3.0` (в проекте `pillow>=12.3.0`), `textual>=0.68.0` (в проекте 8.2.8); `numpy` нужен только через опциональный extra, который мы не тянем.

## Goals / Non-Goals

**Goals:**
- Единая визуальная тема и разметка для всех экранов, читаемость сохраняется при ширине 80 колонок.
- Превью выбранной обложки на шаге «Метаданные и обложка» с автоматическим запасным вариантом на терминалах без графических протоколов.
- Превью тестируется без сети и без реального графического терминала.

**Non-Goals:**
- Зум, панорамирование и пейджер превью; превью на других экранах (например, в `ConfirmScreen`).
- Изменения вывода неинтерактивного режима (`--no-tui`).
- Изменения серверной части и модели `Cover`.

## Decisions

### 1. Зависимость: `textual-image` для превью обложек
Превью рендерит виджет `textual_image.widget.Image` (принимает путь или `PIL.Image`), который сам выбирает лучший доступный протокол: TGP (Kitty), Sixel, иначе — Unicode-фолбэк. Альтернативы: `par-textual-image` (автодетект TGP/Sixel/iTerm2/half-block) — рабочий вариант, но менее обкатан; собственный рендер через half-block/Unicode — низкое качество и лишняя работа. Выбор `textual-image`: он на Pillow (уже в зависимостях), без `numpy`, что держит лёгким standalone-сборку Nuitka (`build-standalone-cli-with-nuitka`).

Важная деталь: терминал для рендера опрашивается на этапе импорта `textual_image.renderable`. Модуль MUST быть импортирован до `App.run()` — импортируем виджет на верхнем уровне `app.py` (до старта приложения). Это также делает доступным Unicode-фолбэк в headless-тестах.

### 2. Инъекция загрузки превью
Добавляется контракт `PreviewFetch = Callable[[str | None], Awaitable[PIL.Image.Image | None]]` как новый инъектируемый параметр `ExporterApp.fetch_preview` — по образцу `load_metadata`/`build`. Боевая реализация скачивает байты обложки по URL через `httpx`-клиент и декодирует их в `PIL.Image`; возвращает `None` при `None`-URL или любой ошибке загрузки. Тесты подставляют заглушку и не обращаются в сеть.

### 3. Размещение превью на экране метаданных
Поле «Обложка» стоит первым в форме. Все поля формы живут в левой колонке, а превью — панель шириной ~40 колонок справа, смещающая их по горизонтали целиком и растянутая на всю высоту формы (`height: 1fr`). Высота картинки — `auto`: виджет `textual_image` берёт ширину панели, а высоту выводит из соотношения сторон изображения, поэтому пропорции обложки не искажаются ни при каком размере. Текстовых медиа-запросов (`@media`) Textual 8 не поддерживает, поэтому перенос панели под поля на узких терминалах обрабатывается программно по размеру экрана (`MetadataScreen.on_resize`): при ширине менее 100 колонок строка `#main_row` перекладывается в вертикаль, а высота панели возвращается к `auto`.

### 4. Состояния панели превью
- «Обложка книги (по умолчанию)» → загрузка `book.cover`.
- Обложка тома → загрузка `cover.url` из `metadata.covers` по `cover_id`.
- «Без обложки» → панель скрывается целиком.
- Если терминал не умеет рисовать изображения (нет TGP/Sixel) → вместо картинки показывается текст «Ваш терминал не поддерживает изображения», загрузка не выполняется. Поддержка определяется `default_terminal_supports_images()` по выбранному `textual_image` рендереру и инъектируется для тестов (`supports_terminal_images`).
- Во время загрузки — текст-плейсхолдер («Загрузка…»), затем изображение либо текст-заглушка при ошибке.
- Кэш по URL на приложении, чтобы возврат «Назад» и повторный выбор не качали одну картинку дважды.

### 5. Единая тема оформления
Вся тема живёт в одном CSS-блоке `ExporterApp` на дизайн-токенах Textual: переопределения базовых переменных (`$primary`, `$accent`, `$surface`, `$panel`, `$text`, `$text-muted`, `$error`, `$warning`) и общие классы: `.screen-title` (заголовок шага вида «Шаг N · …»), `.field_label`, `.section` (разделитель секций), `.actions`, `.error`, `.notice`, `.card` (рамка-контейнер для групп полей). Все экраны переходят на эти классы; точечные правила остаются только там, где экран действительно отличается. Взаимодействие (клавиши, фокус, выбор) не меняется.

## Risks / Trade-offs

- [Превью не отображается на терминалах без TGP/Sixel] → вместо картинки показывается текст «Ваш терминал не поддерживает изображения» (требование «Запасной вариант без поддержки изображений»), выбор обложки не блокируется.
- [Детект терминала зависит от момента импорта] → импорт модуля виджета на верхнем уровне `app.py`; в тестах превью проверяется по состоянию виджета, а не по пикселям.
- [Новая зависимость увеличивает standalone-сборку] → `textual-image` не тянет `numpy`, только Pillow и rich (оба уже есть у проекта).
- [Медленные или битые URL обложек тормозят экран] → асинхронный worker, фиксированный размер превью, кэш по URL, заглушка при ошибке; интерфейс не блокируется.
- [Визуальные регрессии при переделке разметки] → существующие тесты `App.run_test` (включая «узкий терминал») остаются зелёными; добавляются ассерты на превью.

## Migration Plan

- Внедрение по шагам, каждый с зелёными тестами: (1) добавить `textual-image`; (2) тема и разметка; (3) превью обложек.
- Откат: убрать зависимость и вернуть CSS/`app.py` — выбор обложки снова станет текстовым, остальной функционал не затронут.
