## Context

См. `proposal.md` — Why. Текущее состояние, важное для подхода:

- Настройки сжатия сейчас текут как три независимых значения `(max_image_mb, max_image_width, quality)` из `Options` в `ChapterDownloader`, далее в `filter_and_compress` → `should_compress` / `compress_image` (`src/ranobelib_epub/images/pipeline.py`). Качество из CLI жёстко равно `DEFAULT_QUALITY`, хотя в TUI поле качества уже есть и `build_options` умеет его разбирать (`jpeg_quality`).
- `parse_args` заполняет `--max-image-mb` и `--max-image-width` значениями по умолчанию сразу в argparse, поэтому «не задано» и «задано явно» сейчас не различаются.
- Пресеты — новое понятие: их должны уметь разрешать и CLI, и TUI, а часть эффектов (градации серого) относится к слою сборки EPUB, а не к разбору аргументов.

## Goals / Non-Goals

**Goals:**
- Один источник истины для таблицы пресетов и правила взаимоисключения с ручными параметрами.
- CLI и TUI получают одинаковые эффективные настройки сжатия.
- Сохранить текущее поведение по умолчанию (1280 / q80 / 0.5 МБ) без изменений.
- Добавить преобразование в оттенки серого как часть пресета `crosspoint`.

**Non-Goals:**
- Не менять формат вывода (по-прежнему JPEG), дедупликацию и логику скачивания.
- Не добавлять отдельные пресеты под другие модели устройств и не делать таблицу пресетов настраиваемой извне кода.
- Не менять значения по умолчанию и не трогать `--max-image-mb 0` как способ полностью отключить сжатие.

## Decisions

### 1. Новый модуль `images/presets.py` как единственный источник пресетов
Добавляется `src/ranobelib_epub/images/presets.py` с `@dataclass(frozen=True) ImagePreset(name, max_width, quality, max_mb, grayscale)`, словарём `PRESETS`, именем `DEFAULT_PRESET = "medium"` и функцией разрешения:

```
resolve_settings(preset: str | None, *, max_width: int | None,
                 quality: int | None, max_mb: float | None) -> ResolvedSettings
```

`ResolvedSettings` несёт эффективные `max_width, quality, max_mb, grayscale, preset` (имя пресета или `None` для ручного режима). Правило: если `preset` задан и хотя бы один из ручных параметров не `None` — `ArgumentError`; если `preset` задан — берутся значения таблицы; иначе берутся переданные ручные значения, а незаданные падают на значения пресета `medium`.

*Альтернатива:* держать таблицу в `cli/options.py`. Отклонено: тогда слой `epub-build` (градации серого, эффективный порог) зависит от CLI-модуля, а TUI и CLI дублировали бы правило конфликта.

### 2. Отличать «не задано» от «задано» в argparse
Для `--max-image-width`, `--max-image-mb` и нового `--quality` значение по умолчанию становится `None`; `parse_args` вызывает `resolve_settings` и только затем строит `Options` с concrete-значениями. `_validate` проверяет лишь не-`None` значения (нечисловое по-прежнему даёт `ArgumentError`). Дефолт `medium` воспроизводит прежние 1280/q80/0.5.

*Альтернатива:* `argparse.SUPPRESS` и `vars(namespace)`. Отклонено: с `_Parser.error` и ручными проверками `None` читается проще и не ломает `--help`.

### 3. `Options.preset` для отображения и предзаполнения TUI
В `Options` добавляется `preset: str | None = None`; `summary_lines` показывает `пресет: <имя>` либо `пресет: вручную`. Сам `Options` хранит уже разрешённые `max_width/quality/max_mb`, поэтому `main.py` и `ChapterDownloader` не знают о пресетах — они получают готовые числа и флаг `grayscale`.

### 4. Градации серого внутри пайплайна изображений
`should_compress` и `compress_image`, а также `filter_and_compress` получают `grayscale: bool = False`; `ChapterDownloader.__init__` получает одноимённое поле и прокидывает его при вызове. `should_compress` возвращает `True` и тогда, когда запрошены градации серого, а изображение ещё не в режиме `L`/`LA` — так пресет `crosspoint` переводит в серое даже небольшие JPEG. `compress_image` после `flatten_to_white` делает `image.convert("L")` одной операцией декодирования.

*Альтернатива:* отдельный шаг конвертации после `compress_image`. Отклонено: лишнее декодирование и второй проход, а признак «уже серое» пришлось бы проверять повторно.

### 5. Выбор пресета в TUI
В форме параметров добавляется виджет `Select` со значениями «вручную» + имена пресетов. При выборе пресета поля ширины, качества и порога заполняются его значениями и получают `disabled=True`; выбор «вручную» снимает `disabled`. `build_options` получает параметр `preset: str | None`: если пресет выбран, ручные поля текста игнорируются и берутся значения пресета; иначе разбираются поля. Так экран TUI не может создать конфликт — взаимоисключение остаётся инвариантом слоя разбора аргументов CLI.

## Risks / Trade-offs

- **Смена значений по умолчанию argparse на `None`** затронет существующие тесты и любые места, читающие `namespace.max_image_mb` напрямую → митигация: разрешение выполняется внутри `parse_args` до сборки `Options`, а `_validate` проверяет только не-`None`; тесты на дефолты не меняют ожидаемых чисел.
- **Принудительный grayscale для `crosspoint`** может незначительно увеличить отдельные уже маленькие JPEG при перекодировании → приемлемо: целевое устройство — чёрно-белый e-ink, а пресет явно про устройство.
- **Таблица пресетов становится поведенческим контрактом** (значения перечислены в спеке) → изменение чисел в будущем потребует правки спеки; это осознанная плата за предсказуемость.

## Migration Plan

Изменение аддитивно, схема данных и CLI-совместимость сохраняются: запуск без параметров сжатия даёт прежний результат. Правок при развёртывании не требуется. Откат — реверт коммита. Обновить README и текст `--help`; ручной чек: `--preset crosspoint` и ручной режим `--max-image-width 480 --quality 80` дают сопоставимый размер, а `--preset medium --quality 60` завершается ошибкой параметра.
