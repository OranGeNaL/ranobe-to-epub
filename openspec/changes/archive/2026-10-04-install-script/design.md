## Context

См. proposal.md — Why. Существующая поставка утилиты: бинарные файлы для Linux x86_64, macOS arm64 и Windows x86_64 публикуются в GitHub Releases по тегу `v*` вместе с `checksums.txt` (SHA-256). README.md в начале описывает установку через `uv sync`, а готовые бинарные файлы описаны ниже отдельным разделом. Имена артефактов зафиксированы: `ranobelib-epub-linux-x86_64`, `ranobelib-epub-macos-arm64`, `ranobelib-epub-windows-amd64.exe`. Репозиторий — `OranGeNaL/ranobe-to-epub`.

## Goals / Non-Goals

**Goals:**
- Установка в одну строку: `curl -fsSL https://raw.githubusercontent.com/OranGeNaL/ranobe-to-epub/main/install.sh | sh` и `irm https://raw.githubusercontent.com/OranGeNaL/ranobe-to-epub/main/install.ps1 | iex`.
- Скрипты сами определяют последний релиз через GitHub API (`releases/latest`), скачивают подходящий бинарный файл и проверяют его SHA-256 против `checksums.txt`.
- Установка без прав администратора в домашнюю директорию пользователя; понятные сообщения о пути и PATH.
- README.md начинается с раздела «Установка».

**Non-Goals:**
- Не меняется пайплайн сборки и публикации релизов (`.github/workflows/release.yml`).
- Не создаются сборки под новые платформы (macOS Intel остаётся без бинарного файла).
- Не вводится система управления версиями, автозапуск обновлений или проверка наличия более новой версии при каждом запуске утилиты.
- Скрипты не выполняют установку пакетов через менеджеры (brew, apt), не требуют прав root.

## Decisions

**D1. Размещение скриптов в корне репозитория.** `install.sh` и `install.ps1` лежат в корне репозитория и доступны по raw-ссылкам. Альтернатива — папка `scripts/` — усложняет URL в README без выгоды; корень репозитория — общепринятый паттерн (`rustup.rs`, `asdf`). Решение: корень.

**D2. Определение последней версии через GitHub API `releases/latest`.** Скрипт запрашивает `https://api.github.com/repos/OranGeNaL/ranobe-to-epub/releases/latest`, извлекает `tag_name`, затем скачивает артефакт по `https://github.com/OranGeNaL/ranobe-to-epub/releases/download/<tag>/<file>`. Альтернатива — фиксированная версия в скрипте — требует ручного обновления и противоречит требованию «самая свежая версия». Решение: API.

**D3. Целевые директории установки.** macOS/Linux — `~/.local/bin` (стандарт для пользовательских CLI, обычно уже в PATH или легко добавляется). Windows — `%LOCALAPPDATA%\Programs\ranobelib-epub`. Переменная окружения `RANOBELIB_EPUB_INSTALL_DIR` позволяет переопределить путь. Решение: `~/.local/bin` и `%LOCALAPPDATA%\Programs\ranobelib-epub`.

**D4. Проверка целостности через `checksums.txt`.** Скрипт скачивает `checksums.txt` из того же релиза и сверяет SHA-256 скачанного файла. Bash: `sha256sum` (Linux) / `shasum -a 256` (macOS). PowerShell: `Get-FileHash -Algorithm SHA256`. Альтернатива — сравнение только по HTTPS — слабее. Решение: проверка по контрольной сумме.

**D5. Определение платформы и архитектуры.** Bash: `uname -s`/`uname -m`; сопоставление Darwin→macos, Linux→linux, arm64→arm64, x86_64→x86_64. Windows PowerShell: `$env:PROCESSOR_ARCHITECTURE`. Неизвестное сочетание → сообщение и ненулевой код возврата. macOS Intel → явное сообщение и подсказка про uv.

**D6. Строгий режим оболочки.** Bash: `set -euo pipefail`. PowerShell: `$ErrorActionPreference = 'Stop'`. Любая ошибка останавливает скрипт.

**D7. Идемпотентность.** Повторный запуск перезаписывает бинарный файл последней версией без промежуточных вопросов; старые файлы не копятся.

## Risks / Trade-offs

- [Скрипт из `curl | sh` критикуют за безопасность] → Митигация: скрипт консервативен, не выполняет код из аргументов, проверяет SHA-256; в README можно упомянуть возможность скачать скрипт и посмотреть его перед запуском.
- [GitHub API rate limit (60 запросов/час без токена)] → Митигация: скрипт делает один запрос к API; при недоступности API падает с понятным сообщением.
- [`~/.local/bin` может отсутствовать в PATH на macOS] → Митигация: скрипт создаёт директорию и выводит подсказку, как добавить её в PATH.
- [Смена имени артефакта в пайплайне сборки сломает скрипт] → Митигация: имена артефактов зафиксированы в spec `standalone-build` и в `release.yml`; скрипт повторяет их и должен обновляться вместе с ними.
- [PowerShell политика выполнения блокирует `irm | iex`] → Митигация: `iex` исполняет строку без ограничений политики для локального сеанса; это стандартный паттерн.
