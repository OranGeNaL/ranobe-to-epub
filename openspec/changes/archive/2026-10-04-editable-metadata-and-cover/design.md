## Context

См. `proposal.md` — Why. Текущее состояние, важное для решений:

- `Book` (`src/ranobelib_epub/models.py`) — frozen-модель, наполняется парсером `parse_book`; в `package_opf` (`epub/parts.py`) из неё берутся `dc:title`, `dc:creator`, `dc:description`, `dc:subject`, `dc:language`, а `dc:date` — всегда дата сборки.
- Обложка: `parse_cover` уже умеет `default`/`thumbnail`; `ChapterDownloader.fetch_cover(book)` читает `book.cover`, скачивает и сжимает её. Выбора нет.
- `Options` (frozen) — единственный объект параметров, который разделяют CLI и TUI; TUI достраивает его через `build_options`.
- Сценарий TUI: `LinkScreen` → `TranslationScreen` (если есть выбор) → `ConfirmScreen` → `ProgressScreen` → `ReportScreen`. Экран `ConfirmScreen` уже упирается в 80×24, поэтому новые поля туда не помещаются.
- Реальный эндпоинт `GET /manga/{slug_url}/covers` возвращает список объектов `{id, order, info, cover{orig, default, md, thumbnail}}` (проверено на Re:Zero — 46 обложек).
- Карточка `GET /manga/{slug_url}` по умолчанию не содержит автора, жанров и описания (проверено на Re:Zero — они отсутствуют, а на сайте они есть). Эти поля приходят только с расширением полей `?fields[]=authors&fields[]=genres&fields[]=summary`; `authors` — список `{name, rus_name, ...}`, `summary` — ProseMirror-документ, `genres` — список `{name, ...}`.

## Goals / Non-Goals

**Goals:**
- Переопределение метаданных (набор B) до записи файла, одинаково доступное из CLI и TUI.
- Выбор обложки из списка ranobelib и отказ от обложки.
- Сохранение стабильного `dc:identifier` и совместимость вывода при отсутствии переопределений.

**Non-Goals:**
- Редактирование идентификатора, загрузка своей обложки с диска, изменение содержимого глав.
- Новые форматы метаданных сверх EPUB 3 (`dc` + `meta refines`).
- Синхронизация метаданных обратно на сайт.

## Decisions

**1. Переопределения применяются к `Book`, а не проходят отдельным каналом.**
Вводится frozen-dataclass `MetadataOverrides` (все поля — `str | None`, плюс `series_index: int | None`) и функция `apply_overrides(book, overrides) -> Book` через `dataclasses.replace`. `Book` расширяется полями `publisher`, `series`, `series_index` (сайт их не отдаёт — парсер оставляет `None`). Дальше всё ниже по потоку (OPF, nav, NCX, имя файла по умолчанию) уже работает с `Book`, поэтому нового протаскивания не требуется.
*Альтернатива:* передавать `overrides` отдельным аргументом в `package_opf`. Отклонено — разрастается сигнатура и появляются два источника истины для одного поля.

**2. Обложка выбирается URL-ом, загрузка остаётся в `ChapterDownloader`.**
Модель `Cover {id, order, label, url}` и `parse_covers` живут в слое `source`. `RanobeLibSource.fetch_covers(slug)` возвращает список, упорядоченный по `order`; вариант выбирается приоритетом `orig → default → md → thumbnail`, метка — `info`, при пустом `info` — `Том {order + 1}`. Выбор пользователя хранится как `cover_id: int | None` + `cover_disabled: bool`; на этапе сборки id разрешается в `Cover.url`, а в `fetch_cover` передаётся уже готовый URL (сигнатура меняется с `Book` на `str | None`).
*Альтернатива:* тянуть список обложек внутри сборки. Отклонено — список нужен интерфейсу заранее (экран/`--list-covers`), а сборка должна быть детерминированной.

**3. Новый экран TUI вместо расширения `ConfirmScreen`.**
`MetadataScreen` встаёт между `TranslationScreen`/`LinkScreen` и `ConfirmScreen`. Содержимое — в `VerticalScroll`, действия закреплены снизу; список обложек — компактный `Select` со специальными пунктами «Обложка по умолчанию» и «Без обложки». Загруженные обложки и введённые значения хранятся в `ExporterApp`, поэтому возврат назад их не теряет.
*Альтернатива:* добавить поля в `ConfirmScreen`. Отклонено из-за лимита 80×24 (уже проверено на прошлой правке с пресетом).

**4. Флаги CLI — по одному на поле, плюс `--list-covers` и `--no-cover`.**
`--title/--author/--description/--language/--subjects/--date/--publisher/--series/--series-index`, `--cover <id>`, `--no-cover`, `--list-covers`. `--list-covers` печатает обложки и завершается до сборки. Валидация: `--series-index` — неотрицательное целое, `--date` — формат `YYYY-MM-DD`, `--language` — код из набора 10 языков; ошибки дают `ArgumentError`.

**5. Метаданные с сайта дозапрашиваются расширением полей.**
`fetch_book` SHALL запрашивать `fields[]=authors&fields[]=genres&fields[]=summary`. Парсинг: автор — `", ".join(a.name or a.rus_name ...)`, описание — ProseMirror-документ `summary` преобразуется в текст (по `textContent` узлов), жанры — и так уже читаются из `genres[].name` в `parse_genres`. Это чинит пустые значения автора/описания/жанров, из-за которых набор B без этого был бы неполным.
*Альтернатива:* парсить HTML-страницу в поисках автора. Отклонено — расширение полей отдаёт данные в структурированном виде и использует тот же HTTP-клиент.

**6. Язык — фиксированный набор из 10 кодов.**
Константа `LANGUAGE_CODES = ("ru","en","ja","zh","ko","de","fr","es","it","pt")` живёт в `models.py` рядом с `Book`. TUI показывает `Select` с этими кодами, CLI валидирует `--language` против набора. Значение по умолчанию — с сайта (`inLanguage`, обычно `None`), и тогда поле просто опускается.
*Альтернатива:* свободный ввод произвольного BCP-47 кода. Отклонено — выбор из набора проще и предсказуемее для не-ISO значений с сайта.

**7. Серия — только EPUB 3-механизм.**
`belongs-to-collection` + `collection-type=series` + `group-position`. `dc:date` при отсутствии переопределения остаётся датой сборки (`dcterms:modified` не трогаем).

**6. Примерка TUI-полей на существующий стиль.**
Используются те же `compact=True` для `Input`, класс `field_label`, паттерн `preset_row` для строки «метка + поле», чтобы уложиться в терминал.

## Risks / Trade-offs

- [Слишком длинный список обложек (46+) в `Select`] → специальные пункты сверху, ленивая загрузка списка воркером; при недоступности эндпоинта список пуст и доступны только «по умолчанию»/«без обложки».
- [Переопределение названия меняет имя файла по умолчанию] → это осознанное поведение; при `--output` путь не меняется.
- [Серия без номера тома] → `group-position` не пишется, `belongs-to-collection` пишется.
- [Изменение сигнатуры `fetch_cover` затрагивает оба режима] → миграция точечная: CLI и `default_build` передают URL, тесты `fetch_cover` обновляются вместе.
- [Дата в формате, отличном от ISO] → отклоняется до сборки, как и остальные некорректные значения.

## Migration Plan

Изменений данных нет. Обратная совместимость: без новых флагов и без правок на экране TUI поведение и вывод OPF не меняются (новые поля `Book` остаются `None`). README и `--help` дополняются. Откат — снятие новых полей и флагов, поскольку они аддитивны.
