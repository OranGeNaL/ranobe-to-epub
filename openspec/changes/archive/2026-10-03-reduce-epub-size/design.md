## Context

Смотри `proposal.md` — Why. Ограничения, формирующие подход:

- Обработка изображений сейчас идёт двумя фазами: содержимое глав скачивается параллельно, а главы (включая картинки) обрабатываются строго в порядке чтения ([`src/ranobelib_epub/pipeline/downloader.py`](../../../src/ranobelib_epub/pipeline/downloader.py)). Значит, первое вхождение картинки всегда встречается первым — на этом строится дедупликация.
- Условие сжатия вынесено в чистый предикат `needs_compression` ([`images/pipeline.py`](../../../src/ranobelib_epub/images/pipeline.py)), который знает только размер в байтах. Из-за этого PNG 5014 КБ (~4.9 МБ) ниже порога `5.0` остаётся PNG.
- `README.md` уже заявляет дефолт `2`, а код — `5.0`: расхождение существовало до этого изменения.
- Отчёт (`Report`) и его рендер централизованы в [`pipeline/report.py`](../../../src/ranobelib_epub/pipeline/report.py); сюда же добавляется статистика оптимизации.

## Goals / Non-Goals

**Goals:**
- Перекодировать в JPEG все изображения, которые в этом нуждаются: PNG/GIF, слишком широкие, либо крупные JPEG.
- Встраивать байт-идентичные изображения один раз, включая обложку.
- Сделать эффект оптимизации видимым в отчёте.
- Сохранить семантику `--max-image-mb 0` (полное отключение) и `--no-images`.

**Non-Goals:**
- WebP/AVIF и любой формат, кроме JPEG (спека прямо запрещает WebP).
- Изменение дефолтов ширины (`1280`) и качества (`80`).
- Постоянный кеш между запусками и инкрементальная пересборка.
- Дедупликация по URL вместо содержимого (одинаковые картинки на разных URL должны схлопываться).
- Настройка уровня ZIP-сжатия: XHTML уже deflate, JPEG повторно не жмётся.

## Decisions

### 1. Условие перекодирования: формат и размеры в дополнение к порогу

Новый чистый предикат по заголовку изображения:

```
should_compress(size_bytes, image_format, width, height, max_image_mb, max_width) -> bool
```

Возвращает `False`, если `max_image_mb <= 0` (сжатие выключено). Иначе `True`, если `width > max_width`, **или** `image_format != "JPEG"`, **или** `size_bytes > max_image_mb * 1024 * 1024`. `filter_and_compress` открывает изображение один раз, читает заголовок (`format`, `size`) без `load()` и решает по нему; сама перекодировка по-прежнему в `compress_image`.

- **Почему не только снизить порог:** PNG остаются PNG — конвертация в JPEG даёт основную экономию (5014 КБ → ~229 КБ), а порог в байтах формат не учитывает.
- **Почему не «всегда перекодировать»:** уже оптимизированные JPEG перекодировались бы заново, теряя качество без выигрыша и тратя CPU.
- **Размеры читаются заголовком, а не полным декодом** — экономит время на тысячах картинок.

### 2. Дефолт порога: `0.5` МБ

`DEFAULT_MAX_MB` меняется с `5.0` на `0.5`; README приводится к тому же значению. Порог теперь ограничивает только JPEG: PNG/GIF сжимаются по формату, а JPEG крупнее 0.5 МБ — по размеру. Альтернативы: `2` (значение из README — оставляет крупные JPEG) и `0` (слишком близко к полному отключению, ломает смысл «сжатие включено»). Пользователь может вернуть старое поведение через `--max-image-mb 0`.

### 3. Дедупликация по хешу содержимого в `ChapterDownloader`

Добавляется `self._image_cache: dict[bytes, ImageAsset]` на время сборки. В `_prepare_images` (и в `fetch_cover`) после скачивания считается `hashlib.sha1(raw).digest()`:
- попадание — в `resolver` подставляется `href` уже встроенного файла, новый актив не создаётся, `_image_index` не растёт;
- промах — изображение сжимается как раньше, получает имя, кладётся в кеш.

Альтернативы: хеш уже сжатых байтов (пришлось бы сжимать дубликат, чтобы его найти — лишняя работа); кеш на уровне `EpubBuilder` (поздно: картинка уже скачана и сжата, а builder видит только имена файлов); постоянный кеш между запусками (лишнее состояние и инвалидация, вне объёма). Последовательная обработка в порядке чтения гарантирует, что имя первого вхождения стабилизировано, и повторная сборка того же набора даёт тот же архив.

Кеш хранит ссылки на те же объекты `ImageAsset`, что уже лежат в `FetchedChapter.assets`, поэтому пиковая память не растёт: тот же актив попадает в архив один раз, а не дважды.

### 4. Статистика оптимизации в отчёте

В `Report` добавляются `images_deduplicated: int` и `image_bytes_saved: int`. `ReportRecorder` получает метод `image_optimized(original_bytes, final_bytes, deduplicated)`:
- для дедупликатов экономия = размер итогового актива (он не встроен);
- для сжатых — `max(0, original - final)` (отрицательную экономию не показываем, чтобы не путать).

`ReportRecorder.render()` печатает строки «дедуплицировано изображений: N» и «экономия на изображениях: X» только когда значения ненулевые. Это делает результат проверяемым и для TUI, и для текстового режима.

### 5. Прогресс не меняет счёт чисел

`images_total`/`images_done` по-прежнему считают вхождения картинок, а не уникальные файлы: пользователь видит, сколько иллюстраций обработано в тексте, а число встроенных файлов видно в отчёте и в EPUB. Вводить третий счётчик не нужно.

## Risks / Trade-offs

- [Конвертация мелких PNG/логотипов в JPEG даёт артефакты на резких краях] → качество 80 и заливка прозрачности белым уже стандартны; пользователь может поднять `--max-image-width`/`--quality` или отключить сжатие `--max-image-mb 0`.
- [Дедупликация меняет нумерацию файлов при наличии повторов, архив отличается от прежнего] → это ожидаемо и зафиксировано спекой; на книгах без повторов результат побитово не меняется, кроме самой перекодировки PNG.
- [Статистика экономии считается по исходным байтам, а не по размеру в ZIP] → JPEG в ZIP почти не сжимается, поэтому оценка точна; для PNG-оригиналов (`--max-image-mb 0`) статистика не ведётся, так как сжатие выключено.
- [Хеширование SHA-1 на больших объёмах] → стоимость пренебрежима на фоне сетевой загрузки и декодирования Pillow; коллизии для дедупликации картинок не значимы.
- [Изменение дефолта — наблюдаемое изменение поведения] → зафиксировано в спеке и README; старое поведение доступно через `--max-image-mb 0`, откат — реверт коммита.

## Migration Plan

Сервис не разворачивается: изменение входит в следующую версию пакета. После мержа старые команды без флагов дадут меньший EPUB; для сохранения прежнего поведения — `--max-image-mb 0`. Откат — реверт коммита (дефолт и условие сжатия локализованы в `images/pipeline.py` и README).
